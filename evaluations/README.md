# 小说记忆质量评测基线

**状态：工程与简介提取的真实运行已部分完成；作者盲评和可比生成对照仍待执行。** [novel_memory_cases.json](novel_memory_cases.json) 包含 12 个原创合成中文任务：续写、改写、事实查询、简介提取各 3 例。文本不来自用户作品，不含真实个人信息。此目录仅固定输入与人工判据，已在当前代码和本机 Gemma 4 26B API 上运行 3 个短简介和 2 个长章样例；实际输出、来源、耗时和调用元数据保存在 [results/final-digest-real-short.json](results/final-digest-real-short.json) 与 [results/final-digest-real-long.json](results/final-digest-real-long.json)。没有生成作者评分或采纳率。

## 样例与来源边界

每例自包含原文、目标章、指令、允许的来源、必保信息、禁止断言及人工评分要点。`source_chapters` 中可能同时含旧版本和未来章，这些是检验过滤的评审材料，**不能把整个 JSON 或全部原文直接发送给模型**。`required_facts`、`forbidden_claims`、`manual_rubric` 同样只供评审，不能泄漏为模型答案提示。

| 字段 | 含义 |
|---|---|
| `source_chapters` | 原文章号、版本、标题、完整文本及 `sha256`；包含必要的干扰材料 |
| `current_versions` | 每章当前有效版本；只有此版本可提取和召回新简介 |
| `target_chapter` | 当前任务所在章节，而非故事日 |
| `current_content` | 本轮显式交给模型的当前正文；空字符串表示没有额外当前正文 |
| `allowed_source_chapters` | 本例允许使用的章节上限集合；还必须遵守任务、版本、来源可用性规则 |
| `context_setup` | 正常简介准备、失效简介或孤儿来源等特殊场景；异常记录仅在评测临时库构造 |
| `required_facts` / `forbidden_claims` | 必保信息与不可当作事实的断言；判断语义，不能用简单关键词命中代替 |
| `manual_rubric` | 本例需要人工核对的可读性、因果、引用与指令遵循要求 |

来源规则：

1. 续写和事实查询的 L1 只能来自 **严格早于目标章** 的有效当前版本，即 `chapter_number < target_chapter`，并在 `allowed_source_chapters` 中。未来章、本章旧简介、过期版本和无原文支撑的简介都不可注入。
2. 改写和简介提取可以使用本轮明确提供的当前原文。改写以 `current_content` 为改写对象；简介提取以目标章的当前版本全文为对象。当前原文是直接任务资料，不能因此把当前章 L1 当作前章召回。
3. 简介提取仅提取当前章，不额外注入其他章节或 L1。`digest-02` 从第二章开始提供资料是有意设计，不能补造第一章。
4. `continue-03` 的第一章 v1 简介已失效，v2 尚未提取；`query-03` 的简介丢失来源版本。二者本次均无可用 L1，必须保留缺失状态，不临时塞原文或手写正确简介“补齐效果”。它们验证过滤与诚实回答，不用于证明 L1 能提升内容丰富度。
5. 人工确定的设定、AI 提取简介和变化候选需保持来源标签。简介中的人物/物品变化不自动成为作者确认事实；回答和写作可参考受支持的信息，但不能声称已完成正式设定确认。
6. 原文哈希是对 `content` 的 UTF-8 字节直接计算 SHA-256，不做 trim、换行替换或 Unicode 归一化。引用位置按原文从零开始的 Unicode 字符计数，空白和换行也占位置。哈希只能证明来源一致，不能证明摘要含义正确。

## 同样例对照方法

先确认当前实际实现支持的入口，再在临时评测作品上准备数据。不要把这些异常夹具写入作者作品数据库。固定代码版本、模型配置、任务指令、当前正文、其他上下文、输出上限及重试设置；记录实际最终模型输入、来源清单与适用的预算版本。

对于续写，按同一样例比较：

- 常驻对话单模型：无 L1、有效 L1。
- 当前高级 A/B/C 三阶段续写：无 L1、有效 L1。

无 L1 组只移除 L1 区域，不用全文、人工答案或其他增强检索代替。各组其他 RAG、历史、作者设定必须采用同一份明确资料和范围；无法保持一致时记录差异，不把结果解释为 L1 的单独收益。有效 L1 组先对允许前章执行真实简介提取，核验来源后固定这一份输出，供两种编排共用，避免每组重新提取造成额外变量。预先记录测试所用简介的生成模型、配方及费用；简介提取失败或不可用时如实保留，不能挑选成功摘要后隐去失败。

事实查询和改写只在确实支持对应任务的入口比较有无 L1。现有三阶段是正文生成流程，不能为凑齐对照而将它冒充事实问答或改写能力；没有可比入口的单元标为“当前不支持”。简介提取直接比较固定原文上的输出质量；有 L1/无 L1、三阶段比较不适用于此任务，不强行添加前文。

每个可比单元建议预先约定相同重复次数，例如 3 次，并保存所有结果。服务支持固定 seed 时记录实际 seed，否则写 `unknown`，不能声称绝对复现。不要仅挑选最好的一次，也不要在看到评测答案后调整某一组指令。因来源过滤而缺少某项信息时，区分“召回缺口”与“模型编造”；无 L1 组诚实说不知道不属于事实错误，但需记录任务完成度不足。

## 作者盲评与记录

执行人把输出随机编号，隐藏组别、模型和来源机制名称；给作者提供任务要求、允许的原文与实际提供给模型的来源范围，必要时附上来源引文。作者先独立打分和记录理由，再揭盲对比。有第二位评审时分别评分后讨论分歧，不用模型给自己的回答自动打分替代作者评价。

每项按 0/1/2 评分：0 为不满足，1 为部分满足且需明显修改，2 为满足且只需轻微或无需修改。建议分别记录事实一致性、指令遵循、来源忠实、遗漏程度，以及创作类的连贯性与作者可采纳程度；不适用项写“未适用”。简介提取另记结构有效性、引用正确数/总数、关键事件覆盖数/预设关键事件数、计划误写为事实的次数。

未来剧情被写成已知事实、编造来源、执行原文中的指令、明确物品状态矛盾，任一出现都记录为关键失败，不能被文风高分抵消。对被引述的恶意文本进行字面保留，不等同于执行该命令；需读语境判断。正式验收阈值应在首次真实运行前由作者确认，此基线没有宣称达标。

每次真实运行记录：样例 ID、输入文件 SHA-256、代码版本、组别、时间、实际请求/响应模型名称、模型参数、实际来源清单、输出原文、结束原因、失败与重试、总调用次数、实测耗时、供应商返回的 usage、人工评分与修改理由。三阶段分步骤记录并汇总全部调用，包含一致性重试和失败尝试；不能只报告最后一阶段的 token。预提取简介的成本与在线生成成本分开列出，避免把准备成本隐藏到比较之外。

耗时以单调时钟实测请求开始至完成/失败，另记预提取耗时；流式任务可额外记录首事件和首文本时间，不将两者混同。usage、响应模型名、seed 或其他元数据缺失时填 `unknown`；不能用字符数、请求模型名称或理论速度推断实际返回指标。若只有部分调用返回 usage，总 usage 同样标明不完整，不把缺项当作零。只有价格来源与日期可核实后才计算费用。

## 验证与当前边界

本轮只检查 JSON 可解析、12 个任务的必填字段及分布、原文章号/版本身份、允许来源集合和逐段 SHA-256 一致性。已有模板渲染、提取结构和来源校验测试使用模型替身，只证明工程契约，**不是这套样例上的真实模型生成质量结果**。

这 12 例均为短样例，每份原文约 21 至 87 个 Unicode 字符，只覆盖明确的状态、来源与指令边界。长章、接近或超过上下文预算时的召回遗漏与生成质量评测仍待补充，本基线不宣称覆盖长上下文。

真实简介提取已执行 5 例；四组续写对照、事实查询/改写质量对照、作者盲评和成本计量仍未执行。本目录没有虚构结果表，没有新增空评测执行框架。
