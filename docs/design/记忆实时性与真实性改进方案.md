# Nai 记忆实时性与真实性改进方案

更新：2026-09-13。目标是让记忆在作者刚改稿或刚确认状态后尽快失效，同时避免无法证明来源的内容进入高可信上下文。

## 当前已落地

1. **记忆快照版本栅栏**：`ContextPack` 冻结 `scope.memory_head_version`。作者确认、替换、撤销状态或来源失效会推进 `StoryMemoryHead.version`；模型返回和候选落库前重新核验，发现变化就拒绝旧候选。
2. **作品生命周期归属**：公开 StoryFact 创建自动写入 `novel_lifecycle_id`；c0f4a6b8d123 迁移和无历史旧库兼容路径按作品 ID 回填。仍未绑定生命周期的遗留事实从高可信生成上下文排除，并在 manifest 报告 `legacy_unscoped_fact`。
3. **来源与时态门**：L1/L2/L3 继续核验正文版本、字符区间和哈希；计划与已发生剧情分开；同一实体的 owner、holder、quantity 等前置来源失效时，后续状态进入 `needs_review`。
4. **候选与正式事实分离**：AI 提取只能写候选，作者通过 CAS、来源和审计确认后才写入正式 StoryFact；撤销保留历史，不物理抹除证据。

## 推荐的运行模型

```text
作者保存正文
  └─ 同事务：ChapterRevision + L1/L2/L3 失效标记 + 持久任务 outbox
       └─ worker：按 revision/lifecycle/recipe 去重、租约、重试
            └─ 发布前：校验正文哈希 + 记忆 head 版本 + 任务 CAS
                 └─ ready 记忆进入 ContextPack；冲突/过期只进待核对
```

实时性不应靠“每次请求都重新让模型总结”实现，而应靠版本号、事务 outbox、任务去重和发布前 CAS 实现。这样能把延迟控制在保存事务 + worker 调度范围内，也不会让模型调用直接阻塞作者保存。

真实性不应依赖模型置信度。每条高可信记忆至少要回答：来自哪一版原文、原文哪一段、属于哪个作品生命周期、在什么章节生效、是否经过作者确认。回答不了其中任一项，就显示为候选、待核对或不可用。

## 仍需补强

- L2/L3 的结构化提取入口目前是显式任务，尚未完全接入“保存后自动排队、合并连续改稿、失败可恢复”的独立持久 worker。
- 当前来源引用仍以 JSON `source_refs` 保存，长期可迁移为规范化 `memory_sources` 表，增加数据库外键和唯一约束，降低手工写库绕过校验的风险。
- 目前按章节边界生效；需要场景/段落锚点时，应扩展 `effective_position`，同时保留章节级回退规则。
- 发现来源冲突时现在主要阻断并提示；后续可增加冲突卡片，显示两条证据、时间范围和作者选择，而不是只显示计数。
- 真实质量仍需作者盲评：自动化只能证明来源和状态协议，不能证明摘要没有遗漏或写作结果可采纳。
